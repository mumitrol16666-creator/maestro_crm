# WhatsApp browser worker — этап 1

Отдельный процесс открывает WhatsApp Web через Playwright и передаёт входящие сообщения
в CRM. AI в worker отсутствует. По умолчанию включён безопасный режим `observer`,
который физически не забирает исходящие сообщения из очереди.

## Запуск пилота

```bash
cd automation/whatsapp-worker
cp .env.example .env
npm install
npx playwright install chromium
npm start
```

В `.env` worker и `backend/.env` должен стоять одинаковый
`WHATSAPP_BROWSER_WORKER_SECRET`. Профиль Chromium хранится вне Git в
`WHATSAPP_SESSION_PATH`; после первого запуска нужно один раз отсканировать QR-код.
В серверном headless-режиме worker передаёт свежий QR в защищённый раздел
`CRM → WhatsApp`, где в строке состояния появляется кнопка «Показать QR».

По умолчанию worker импортирует сообщения только из открытого в WhatsApp Web диалога.
`WHATSAPP_BROWSER_OPEN_UNREAD_CHATS=true` разрешает ему самому открывать непрочитанные
диалоги, но WhatsApp при этом помечает их прочитанными. Для первого пилота оставьте
значение `false`.

После проверки входящего контура можно явно установить
`WHATSAPP_BROWSER_MODE=manual`. Тогда worker отправляет только те сообщения, которые
администратор сам написал в CRM после нажатия «Забрать диалог». Если worker не может
доказать отправку по ID сообщения, запись получает статус `uncertain` и автоматически
повторно не отправляется.

## Ограничения этапа

- WhatsApp меняет DOM без предупреждения, поэтому селекторы проверяются на отдельном
  тестовом аккаунте перед включением на рабочем номере.
- Группы и статусы не импортируются.
- AI-ответов нет. Рассылка только из «Напоминаний» CRM и только при `WHATSAPP_BROWSER_BROADCAST=true`.

## Рассылка из «Напоминаний»

В CRM в разделе «WhatsApp» (вкладки очередей) кнопка «Разослать всем» ставит тексты карточек
текущего фильтра в очередь. Паузу между сообщениями (3 минуты) держит CRM: воркер получает
следующее сообщение через `POST /broadcast/claim`, только когда пауза прошла, поэтому
даже два воркера не отправят чаще.

Воркер открывает `web.whatsapp.com/send?phone=…&text=…`, проверяет, что текст встал в поле,
жмёт Enter и ждёт в чате новую строку с этим текстом и галочкой сервера. Результаты:

- `sent` — CRM ставит ту же отметку «Отправлено», что и галочка администратора;
- `invalid` — номера нет в WhatsApp;
- `failed` — до Enter не дошло, сообщение не ушло;
- `uncertain` — Enter нажат, но подтверждения нет. Повторно такое сообщение не отправляется,
  как и сообщение, по которому воркер не отчитался за 10 минут.

Ещё два статуса ставит сама CRM: `expired` — время напоминания прошло (для «Сегодня урок»
это начало урока), `duplicate` — тот же текст на тот же номер уже в рассылке: уходит одно
сообщение, отметку «Отправлено» получают обе карточки. Пока карточка в рассылке, ручные кнопки
и правка текста на ней закрыты. Рассылка одна за раз.

Когда воркер открывает чат получателя, непрочитанные сообщения этого человека на телефоне школы
становятся прочитанными. Окно Chrome воркера для работы людей не использовать: во время рассылки
оно перезагружается каждые 3 минуты.

Включается отдельно: `WHATSAPP_BROWSER_BROADCAST=true`. Режим `observer` при этом можно оставить.

## Воркер на компьютере школы (Mac или Windows)

Вход в WhatsApp хранится на том компьютере, где работает воркер. На сервере воркер тогда
выключают: два воркера с одним `WHATSAPP_BROWSER_ACCOUNT_KEY` перехватывают сессию друг у друга.

```bash
cd automation/whatsapp-worker
npm ci
```

Настройки (файл `.env` рядом или переменные окружения):

```
WHATSAPP_BROWSER_CRM_URL=https://crm.maestro.com.kz
WHATSAPP_BROWSER_WORKER_SECRET=<тот же, что в backend/.env на сервере>
WHATSAPP_BROWSER_ACCOUNT_KEY=maestro-main
WHATSAPP_BROWSER_WORKER_ID=maestro-mac-1
WHATSAPP_SESSION_PATH=<папка вне репозитория>
WHATSAPP_BROWSER_HEADLESS=false
WHATSAPP_BROWSER_CHANNEL=chrome
WHATSAPP_BROWSER_BROADCAST=true
```

`WHATSAPP_BROWSER_CHANNEL=chrome` берёт установленный Google Chrome, скачивать Chromium не нужно.
Запуск `npm start`, в открывшемся окне Chrome один раз отсканировать QR телефоном школы.
Пока идёт рассылка, компьютер не должен засыпать.
