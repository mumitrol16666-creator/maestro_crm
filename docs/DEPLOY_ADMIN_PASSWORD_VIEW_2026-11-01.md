# Выкатка: просмотр пароля в CRM (01.11.2026)

Задача для Codex и шаги для Владислава. Выкатывается только CRM. Учебную платформу не трогать.

## Что едет

Ветка `release/admin-password-view-20261101`, PR в `main`. Это прод `9c921d0` и три коммита сверху:

- админ видит текущий пароль пользователя («Пользователи» → «Пароль», карточка ученика → «Показать пароль»);
- при смене пароля можно вписать свой пароль, а не только сгенерированный;
- журнал интеграции больше не повторяет запросы со скрытыми данными, кеш повторных запросов не хранит пароли;
- проверка выкатки требует ключ `CRM_PASSWORD_VAULT_KEY`.

Миграция одна: `20261101100000_student_password_copy`. Она только добавляет две пустые колонки в `Student`. Данные не меняются.

Три коммита ветки `codex/stage0-approve-callback-20261017` (`b145adb`, `e7f36e2`, `57a7958`) в эту выкатку не входят.

## Шаг 1. Ключ. Делает Владислав сам, до слияния PR

Ключ не отправлять в чат, в задачу Codex и в git.

1. Зайти на сервер: `ssh -p 14579 root@178.105.59.89`.
2. Проверить, что ключа ещё нет. Команда ничего не должна вывести:

   ```bash
   grep '^CRM_PASSWORD_VAULT_KEY=' /var/www/maestro_crm/backend/.env
   ```

3. Создать ключ сразу в файле:

   ```bash
   echo "CRM_PASSWORD_VAULT_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64'))")" >> /var/www/maestro_crm/backend/.env
   ```

4. Показать строку и сохранить её в менеджер паролей:

   ```bash
   grep '^CRM_PASSWORD_VAULT_KEY=' /var/www/maestro_crm/backend/.env
   ```

   Без этой копии все сохранённые пароли станут нечитаемыми при потере сервера. Менять ключ потом нельзя: старые копии перестанут открываться.

Если ключа нет или он неверный, выкатка остановится на шаге `release:preflight` с понятной ошибкой. Работающий CRM при этом не перезапускается.

## Шаг 3. Проверка после выкатки. Делает Codex

```bash
curl -s https://app-maestro-school.duckdns.org/api/health
```

`releaseSha` равен коммиту слияния в `main`.

На сервере:

```bash
cd /var/www/maestro_crm/backend
set -a; source .env; set +a
psql "${DATABASE_URL%%\?*}" -Atc "SELECT migration_name FROM _prisma_migrations WHERE migration_name = '20261101100000_student_password_copy' AND finished_at IS NOT NULL"
pm2 logs maestro-crm-backend --lines 200 --nostream | grep -i passwordVault
```

Первая команда выводит имя миграции. Вторая ничего не выводит.

Не менять пароли настоящих пользователей ради проверки.

## Шаг 4. Проверка глазами. Делает Владислав

1. Войти в CRM под супер-админом.
2. «Пользователи» → в своей строке «Пароль». Откроется окно «Пароль не сохранён», это нормально для паролей, заданных до выкатки.
3. Вписать свой новый пароль и сохранить.
4. Снова нажать «Пароль». CRM показывает этот пароль и время.
5. «Журнал действий»: есть записи «Сброс пароля» и «Просмотр пароля».

## Откат

1. Сделать `git revert -m 1 <коммит слияния>` в `main` и запушить.
2. Запустить ту же выкатку с `target: crm`.

Колонки в базе останутся. Старый код их не читает, это безопасно. Резервная копия базы создаётся выкаткой сама, в каталоге резервных копий CRM на сервере.

## Что важно знать

- Старые пароли показать нельзя никогда. Есть только их хеш. Пароль становится видимым после того, как его задали в CRM после выкатки.
- Если ученик сам меняет пароль в приложении, CRM этого пока не узнаёт и покажет прежний. В окне есть предупреждение. Исправление делается отдельной задачей.
- Админ видит пароли всех, кроме админов. Пароли админов видит только супер-админ. Отключается в настройках роли правом «Создание пользователей».
