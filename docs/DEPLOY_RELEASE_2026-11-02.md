## Почему такой порядок

- CRM при просмотре пароля спрашивает приложение, когда пароль меняли там. Старое приложение этого не умеет, и CRM откажет в показе паролей всех привязанных учеников и преподавателей.
- Выкатка приложения на сервере тоже подтягивает свежий `main` CRM. Если слить PR CRM раньше, новый интерфейс CRM окажется на сервере до нового бэкенда. Поэтому PR CRM сливается только непосредственно перед выкаткой CRM.

## Шаг 1. Ключ. Делает Владислав сам, до шага 4

Ключ не отправлять в чат, в задачу Codex и в git.

1. Зайти на сервер: `ssh -p 14579 root@178.105.59.89`.
2. Проверить, что ключа ещё нет. Команда ничего не должна вывести:

   ```bash
   grep '^CRM_PASSWORD_VAULT_KEY=' /var/www/maestro_crm/backend/.env
   ```

3. Создать ключ сразу в файле:

   ```bash
   echo "CRM_PASSWORD_VAULT_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64'))")" >> /var/www/maestro_crm/backend/.env
   ```

4. Показать строку и сохранить её в менеджер паролей:

   ```bash
   grep '^CRM_PASSWORD_VAULT_KEY=' /var/www/maestro_crm/backend/.env
   ```

Ключ нельзя менять и нельзя терять: без него сохранённые пароли не откроются. Если ключа не будет, выкатка CRM остановится на проверке до перезапуска, и работающая CRM не пострадает.

## Откат

Приложение и CRM откатываются отдельно: `git revert -m 1 <коммит слияния>` в `main`, push, тот же workflow с той же целью. Откатывать в обратном порядке: сначала CRM, потом приложение.

Новые колонки и таблицы старый код не читает, их можно не удалять. Резервные копии баз выкатка делает сама перед миграциями.

## Что остаётся открытым после выкатки

- Старые пароли показать нельзя, только задать новые.
- Если CRM привязывает уже существующий аккаунт приложения со своим паролем, в CRM может остаться старая копия.
- Отмена урока учителем с причиной уходит админу как отсутствие. Вид отсутствия и списание выбирает админ при подтверждении. CRM теперь показывает причину учителя и подсказывает «уважительная», но решение за админом.
- Откат раннего урока, когда поздний уже применён, не трогает Points позднего урока.
